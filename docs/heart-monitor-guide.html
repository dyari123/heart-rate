Heart Monitor v3.3

How the code works: every part, every function and every setting, explained in plain words.

Heart rate Blood oxygen Temperature Screen, sound and output I²C bus and control

Each colour marks one part of the program and stays the same in every diagram, table and card below. This is a hobby project, not a medical device.

01 · Overview

The big picture

The Nano runs three measurements at the same time on one small chip with 32 KB of program space and 2 KB of memory. A fingertip on the MAX30102 gives heart rate and blood oxygen, the GY-906 measures temperature without contact, and the OLED, buzzer and USB serial line show the results.

MAX30102 · IR light

Heart rate

Infrared light shines into the fingertip. Each heartbeat pushes blood in, the reflected light dips, and the code times those dips to get BPM.

MAX30102 · Red + IR

Blood oxygen

Oxygen-rich blood absorbs red and infrared light differently. The ratio of the two pulse sizes gives an SpO2 estimate.

GY-906 · MLX90614

Temperature

A thermopile reads the infrared heat given off by whatever is in front of it, twice a second.

SSD1306 · D8 · USB

Screen, sound, output

The OLED redraws 10 times a second, the buzzer beeps, and one text line per second goes to the laptop.

02 · Program flow

How the program runs

Like every Arduino sketch, it has two parts: setup() runs once at power-on, then loop() repeats forever, thousands of times a second.

setup(): once, at power-on
  1. Buzzer off, Serial at 115200 baud.
  2. OLED started at 100 kHz and shows Starting... for 0.8 s.
  3. MAX30102 started. If it does not answer, the screen shows SENSOR ERROR and the program stops.
  4. Sensor configured: LED current 0x1F, average 4 samples, Red + IR mode, 400 samples/s, 411 µs pulses, 4096 nA range. FIFO cleared.
  5. Bus forced back to 100 kHz in case a library changed it.
  6. MLX90614 checked once; Serial says FOUND or NOT FOUND.
  7. resetMeasurement() puts everything in its starting state.
The loop never waits

Nothing in loop() uses delay(). Each job checks a timer and runs only when its turn has come, so reading the sensor is never held up by the slower screen.

Two clocks are used. sampleClock adds 10 ms for every sensor sample and times heartbeats precisely. millis() drives the screen, the timers and the 30-second cycle.

03 · Heart rate

From light to heartbeat

Every 10 ms the MAX30102 produces one Red and one IR reading. Each reading travels through the same seven steps until it either becomes part of a heartbeat or is thrown away.

1

Read every sample pumpSensor(), read18()

The MAX30102 keeps up to 32 samples in its own memory (the FIFO). The code reads three registers in one go, starting at 0x04: the write pointer, the overflow counter and the read pointer. The difference between the pointers is how many new samples are waiting.

  • Samples are read 5 at a time: 5 × 6 bytes = 30 bytes, which fits the Nano's 32-byte I²C buffer.
  • Each sample is Red (3 bytes) then IR (3 bytes). read18() joins the bytes and keeps the 18 data bits (& 0x3FFFF).
  • The block is copied into redBuf and irBuf first and processed afterwards, so no other I²C message (such as an LED change) can interrupt a read.
  • If the overflow counter is not 0, samples were lost and are added to samplesLost.
byte count = (wr - rd) & 0x1F;          // samples waiting (pointers wrap at 32)
if (ovf > 0) {
  if (count == 0) count = 32;           // FIFO completely full
  if (fingerPresent) samplesLost += ovf;
}
2

Is a finger there? handleSample()

Every sample first adds 10 ms to sampleClock. Then the IR level decides whether a finger is present. A finger reflects much more infrared light than open air.

  • No finger yet: IR above 20000 for 10 samples in a row (0.1 s) calls startMeasurement().
  • Finger present: IR below the off level for 25 samples (0.25 s) prints FINGER REMOVED and calls resetMeasurement().
  • The off level follows the LED current: 12000 × irPower / 0x1F. A dimmer LED gives lower readings, so the threshold moves down with it.
3

Settle and tune the LEDs processSample(), tunedPower()

For the first 400 ms after a finger arrives, no beats are counted. The baseline follows fast (DC_ALPHA_FAST = 0.1) and the LED currents are adjusted so the signal is strong but not clipped.

  • Every 5 samples (50 ms), each LED is checked. If its raw level is outside 100,000 to 200,000, the new current is power × 150000 ÷ level, kept between 0x04 and 0x7F.
  • IR and Red are tuned separately. The SpO2 maths divides each colour by its own level, so they do not need equal currents.
  • At most 6 changes per measurement. After a change, 6 samples are skipped (they were taken with the old current) and the filters restart.
level 60,000 at power 0x1F (31) → 31 × 150000 ÷ 60000 = 77 = 0x4D
4

Clean the signal processSample(), lowPass()

The raw IR value is a large steady level (the DC, around 100,000 to 200,000) with a tiny heartbeat ripple on top (the AC, often under 1%).

  1. Remove the baseline. irDC follows the raw value slowly (DC_ALPHA = 0.02, about 0.5 s). Subtracting it leaves only the ripple.
  2. Flip it. Blood absorbs light, so each beat makes the reading drop. irDC − ir turns every beat into an upward bump.
  3. Smooth it. lowPass() is a 2nd-order Butterworth filter at 5 Hz. It removes fast noise and delays every beat by the same amount, so the time between beats is unchanged.
irDC += alpha * ((float)ir - irDC);      // slow baseline
irAC  = lowPass(irDC - (float)ir, irLP); // flipped, filtered heartbeat

Three safety checks also run here:

  • Clipped: raw IR or Red above 260000 marks the next 0.5 s as clipped.
  • Moved: every 0.5 s, if irDC changed by more than 3%, beats are ignored for 1 s.
  • Lost: no accepted beat for 3 s calls signalLost(), which clears the history so the screen shows -- instead of an old number.
5

Find each beat peak / valley detector in processSample()

The detector switches between two states: looking for a valley and looking for a peak. It only accepts a turn when the wave has moved back by the hysteresis: 30% of a typical beat, and never less than 40. Small wiggles and the second bump of each heartbeat (the dicrotic notch) are too small to count.

  • While the wave rises, the code remembers the largest slope and when it happened (maxSlope, maxSlopeTime).
  • When the peak is confirmed, a parabola through the three slopes around that point finds the true moment between two samples. That gives about 1 ms precision instead of 10 ms.
  • The pulse size is peak − valley. The Red signal is sampled at the same two moments, for SpO2.
float denom = slopeBeforeMax - 2 * maxSlope + slopeAfterMax;
if (denom < 0) offset = 0.5 * (slopeBeforeMax - slopeAfterMax) / denom;  // -0.5 .. +0.5 sample
unsigned long beatTime = maxSlopeTime + (long)(offset * SAMPLE_MS + 0.5);
6

Check the beat, then count it onPulse(), addInterval()

Every candidate beat passes these checks in order. The first one that fails decides what happens.

  • APulse smaller than 80ignored as noise
  • BLess than 300 ms since the last beat (faster than 200 BPM)ignored
  • CPerfusion index (pulse ÷ DC × 100) below 0.15%: weakrejected
  • DDuring a motion pause or clippingrejected
  • ESmaller than 0.3 × the usual pulserejected
  • FBigger than 3 × the usual pulse. Two in a row means the pulse really got stronger, so the usual size is learned again.rejected once
  • ✓Passed: the usual size is updated (80% old + 20% new), the heart icon flashes, SpO2 gets a new ratio.accepted

An accepted beat gives an interval: the time since the previous beat. That interval is then handled like this:

  • First beat: only its time is stored.
  • About 2 or 3 normal intervals long: weak beats in between were missed, so the gap is split into equal parts.
  • No history yet and 1.5 to 3 s long: treated as one missed beat and halved.
  • Up to 1.5 s (40 BPM or faster): passed to addInterval().

addInterval() compares the interval with the median of the stored ones. More than 25% away counts as an odd interval and is not stored. Three odd ones in a row mean the heart rate really changed, so the history is cleared and starts again. Good intervals go into a ring of the last 8 (ibi[]) and into the 30-second total.

7

Turn intervals into BPM computeBPM(), once a second

The last 8 intervals are sorted. With 5 or more, the shortest and the longest are dropped (a trimmed mean), so one badly timed beat cannot pull the number. Then BPM is 60,000 ms divided by the average interval.

intervals (ms): 820 830 835 840 845 850 860 1000 drop shortest and longest → 830 835 840 845 850 860 sum = 5060 over 6 intervals BPM = 60000 × 6 ÷ 5060 = 71.1 → 71 BPM
return (int)(60000.0 * CLOCK_FIX * n / sum + 0.5);
04 · Rolling average

The 30-second average

The measurement is split into back-to-back 30-second cycles, counted from the moment the finger arrives. The clock in the bottom-right corner of the screen counts 0 to 29 s and starts again.

  • During a cycle, every good interval is added to intervalSumCycle and counted in intervalCountCycle.
  • When a cycle ends, averageBPM() computes 60000 × count ÷ total. This uses every good beat in the cycle, so it is steadier than the live number.
  • The result is stored in lastAvg, shown on screen as Avg:71bpm (when no warning is showing), and printed as a --- 30s AVG --- block on Serial.
  • The cycle counters then reset and the next cycle starts. The average keeps refreshing every 30 s for as long as the finger stays on.
a 30 s cycle with 36 good intervals totalling 30,240 ms average = 60000 × 36 ÷ 30240 = 71.4 → Avg:71bpm
05 · Blood oxygen

How SpO2 is estimated

Oxygen-rich blood absorbs less red light than oxygen-poor blood, while infrared is affected much less. Comparing how strongly the pulse shows up in each colour gives a ratio called R.

R = (redPulse ÷ redDC) ÷ (irPulse ÷ irDC) SpO2 = 110 − 25 × R
  1. updateSpO2() runs for every accepted beat and computes R from that beat.
  2. Ratios outside 0.1 to 2.0 are impossible and are dropped.
  3. The last 8 ratios are kept. Their median is used (the average of the middle two when the count is even), so one bad beat cannot move it.
  4. After 2 good beats, SpO2 = 110 − 25 × median R, rounded.

The 90 to 97% window is a display rule

This version caps the shown value at SPO2_MAX_SHOWN = 97 and hides anything below SPO2_MIN_SHOWN = 90 as --. So a reading of 97% means "97 or higher", and -- can mean either "not enough beats yet" or "the formula gave under 90". The real ratio is always printed on Serial as Rx1000.

To calibrate, compare with a pharmacy fingertip oximeter: SPO2_A = oximeter SpO2 + 25 × R, averaged over many sessions. SpO2 from this sensor stays an estimate.

06 · Temperature

Reading the GY-906 directly

The MLX90614 is read with the plain Wire library instead of an extra library, which saves program space. updateTemperature() asks for register 0x07 (object temperature) every 500 ms.

The I²C conversation
  1. Send the register number 0x07 with a repeated start (endTransmission(false)), as the MLX90614 requires.
  2. Read 3 bytes: low byte, high byte, and a checksum (PEC) that is skipped.
  3. If bit 15 is set, the sensor reports an error and the old value is kept.
Integer maths, no floats

The sensor counts in steps of 0.02 Kelvin. The code keeps temperature in tenths of a degree, which avoids slow, large floating-point code.

tenths = (2 × raw − 27315) ÷ 10 (rounded) raw 15475 → (30950 − 27315) ÷ 10 = 364 → 36.4 °C

Before the first reading, currentTempTenths is -9999, which the screen and Serial show as --. With nothing in front of it, the sensor sees the room, so the reading is close to air temperature. A finger or object in front switches it to that surface temperature.

07 · Screen and buzzer

What the OLED shows

The SSD1306 is 128 × 64 pixels. U8g2 draws it in 8 strips (page mode) to save memory, and pumpSensor() runs between strips so no samples pile up while the screen is sent.

StatusWhenLine 2 on screenSerial word
Clippedraw value above 260,000 in the last 0.5 sPress lighterclip
Movingbaseline jumped more than 3% in 0.5 s (1 s pause)Hold stillmove
Weaklast pulse under 0.15% perfusionWeak pulseweak
OKnone of the above, or still settlingAvg:71bpm once a cycle has finishedok

The checks run in this order, so Press lighter wins over Hold still, which wins over Weak pulse.

The moving wave

The wave is a drawing, not a real ECG. ecgWave[] holds 64 points, drawn 2 pixels apart. Every 25 ms it shifts one step left, so the screen shows 1.6 s. Normally it repeats a gentle 16-step idle pattern; on each accepted beat it inserts an 8-step spike. Both patterns are stored in flash with PROGMEM to save memory.

The buzzer

updateEverySecond() plays a short 70 ms tone at 1568 Hz (the note G6) once a second, whenever a BPM value is available. The heart icon, by contrast, flashes on each accepted heartbeat.

12 · Things to know

Things to know about this version

These are not bugs that stop the device from working, but they are worth knowing when you describe the project or change the code.

The beep is once a second

The tone is played in updateEverySecond(), not on each heartbeat. Your project PDF describes one beep per heartbeat. To beep on every beat instead, move the tone() line into beatFeedback().

SpO2 is shown inside 90 to 97%

Values above 97 show as 97 and values below 90 show as --. Mention this in any report, and use Rx1000 on Serial for the real ratio.

Some values are counted but never printed

samplesLost, beatsRejectedCycle and min/maxBPMCycle are tracked but not shown. IRREGULAR_LIMIT is not used, and mlxFound only sets the startup message. You could print them or delete them to free flash.

CLOCK_FIX is still 1.000

Every BPM is multiplied by it. Leave it unless repeated tests show the sensor clock differs from real time by more than 0.5%.

13 · Words

Glossary

PPG
Photoplethysmography: measuring blood volume changes with light. It is what the MAX30102 does.
DC and AC
DC is the large, steady part of the light reading. AC is the small ripple caused by each heartbeat.
Perfusion index
The pulse size as a percentage of the DC level. Low means weak blood flow, often from cold fingers or pressing too hard.
FIFO
"First in, first out": the sensor's 32-sample memory that holds readings until the Nano collects them.
I²C
A two-wire bus (SDA data, SCL clock) shared by several devices, each with its own address.
Hysteresis
A minimum change required before the detector switches state, so small wiggles do not count as peaks or valleys.
IBI
Inter-beat interval: the time between two heartbeats in milliseconds. BPM = 60,000 ÷ IBI.
Dicrotic notch
A small second bump in each pulse, caused by the aortic valve closing. It must not be counted as a beat.
Trimmed mean
An average taken after dropping the smallest and largest values.
Median
The middle value after sorting. One extreme value cannot move it much.
Butterworth filter
A smooth low-pass filter: it lets slow changes (heartbeats) through and removes fast noise.
PROGMEM
Keeps constant data in the Nano's flash instead of its small 2 KB RAM.
